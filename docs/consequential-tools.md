# Consequential tool contracts

Every host-persistent MCP tool is controlled by local configuration. Client confirmation annotations are not an authorization boundary.

| Tool | Exact authority | Frozen state and race validation | Idempotence and replay | Local control |
| --- | --- | --- | --- | --- |
| `write_text_document` | Create or atomically replace one `.md` or `.txt` regular file beneath the operation root. | No proposal. An optional `expected_hash` protects updates; the implementation rechecks the existing content hash and pinned parent immediately before atomic replacement. Symlinks, Git metadata, blocked paths, invalid text, and oversized content are rejected. | Declared non-idempotent because it creates an audit event and may cross create/update or concurrent-state boundaries. There is no proposal replay record. | Total write switch plus document-write switch. |
| `patch_text_document` | Apply exact text replacements to one existing `.md` or `.txt` file. | No proposal. Exact context must exist and be unique unless `replace_all` is set. Optional `expected_hash`, a second content-hash check, and pinned-parent replacement detect races. | Non-idempotent: a second call normally fails because its old context is gone. No proposal replay record. | Total write switch plus document-write switch. |
| `move_text_document` | Move one existing `.md` or `.txt` file to a new, nonexistent document path on the same filesystem. | No proposal. Optional `expected_hash`, content recheck, pinned source/destination parents, no-follow opens, and exclusive destination linking detect changes and collisions. | Non-idempotent: replay fails because the source no longer exists or the destination exists. No proposal replay record. | Total write switch plus document-write switch. |
| `git_stage` | Stage explicit safe paths, or all current safe changes, in one local repository beneath the operation root. | No proposal. The repository and requested paths are canonicalized immediately; blocked files, executable filters, unsafe Git features, and remote operations are rejected. | Idempotent for the same repository state. No proposal replay record. | Total write switch plus local-Git-write switch. |
| `git_unstage` | Unstage explicit paths, or the whole local index, without changing worktree files. | No proposal. Repository/path validation is immediate and Git is run with fixed noninteractive safety configuration. | Idempotent for the same repository state. No proposal replay record. | Total write switch plus local-Git-write switch. |
| `prepare_git_commit` → `execute_proposal` | Create exactly one local commit; never contact a remote or change other Git history. | The proposal freezes repository, branch, `HEAD`, unborn state, index bytes/tree, selected worktree state, target tree, message, and full file list. Execution rebuilds and compares that plan before and during atomic claim. | The proposal is short-lived and atomically moves out of `pending`; replay cannot create a second commit. | Execution requires the total write switch plus local-Git-write switch. |
| `prepare_existing_script_run` → `execute_proposal` | Run one pre-existing script beneath the operation root with frozen arguments and a minimal host environment. It cannot accept inline shell or create/replace the script. | The proposal freezes canonical script and working-directory identities, inode/device/mode, script hash, interpreter, arguments, timeout, output limit, environment profile, and impact summary. Execution revalidates, pins file descriptors, and runs a hash-checked snapshot. | The proposal is short-lived and atomically claimed; replay cannot run the script twice. | Preparation and execution require the total write switch plus existing-script-run switch. |
| `prepare_approval_smoke` → `execute_proposal` | Create one root-owned empty `smoke-<uuid>.empty` file in the fixed approval-smoke directory. No caller path, filename, or shell input is accepted. | Preparation freezes the canonical directory, generated filename, and the root-owned enable file's path, device, inode, and modification time. Execution revalidates that state and creates the target exclusively. | The proposal is short-lived and atomically claimed; the generated name and exclusive create prevent duplicate effects. | Preparation requires `/var/lib/shellbridge/approval-smoke/enabled`: a regular root-owned file in a root-owned directory, with neither object group- nor world-writable (mode `0600` recommended). Removing that file disables preparation. Execution also requires the total write switch. This is an administrator acceptance-test facility, not a general file tool. |
| `cancel_proposal` | Change one pending proposal to cancelled without performing its host operation. | The proposal identifier and current pending state are checked atomically in SQLite. | Idempotent in host effect; a repeat cannot re-cancel or execute the proposal. | Authenticated owner access; no host-write capability switch because cancellation only removes authority. |
| `execute_proposal` | Execute only the already-frozen Git, script, or approval-smoke plan identified by `approval_id`. It accepts no overriding body fields. | Integrity hash, owner, expiry, pending state, relevant capability state, and operation-specific frozen state are validated before and during atomic claim. | Idempotent in host effect: only one claim can execute; repeats return a non-executable state. | Total write switch, plus the proposal kind's capability-specific control where applicable. |

Proposal payloads are sealed in SQLite, expire by default after ten minutes, belong to the single stable owner principal, and retain their terminal state for audit and replay prevention.
